# Project Intelligence

## Purpose

`.agents/skills/project-intelligence/` holds a second, agent-owned knowledge
model of this repository, separate from `docs/`. This document explains what it
is, how it differs from the documentation system, and when to distrust it.

It is written here because the system is otherwise invisible: nothing under
`docs/` referenced it, and an agent that discovered `knowledge/architecture.md`
on its own had no way to know how much authority that file carries.

## What it is

| Path | Holds |
| --- | --- |
| `.agents/skills/project-intelligence/SKILL.md` | The skill definition and navigation entry point |
| `.agents/skills/project-intelligence/knowledge/INDEX.md` | Index of the knowledge modules |
| `knowledge/architecture.md` | Architectural invariants |
| `knowledge/packages.md` | Sealed packages and ownership |
| `knowledge/dependencies.md` | Dependencies and vendor SDKs |
| `knowledge/runtime-flows.md` | Runtime and execution flows |
| `knowledge/data-flows.md` | Data flows and storage topology |
| `knowledge/conventions.md` | Development conventions |
| `knowledge/decisions.md` | Architectural decisions |
| `knowledge/risks.md` | High-risk areas and technical debt |
| `knowledge/unresolved.md` | Open questions and an inspection log |

## How it differs from `docs/`

They answer different questions and have different standing.

`docs/` is the **contract surface**. It is validated (`npm run docs:ci`), its
generated half is rebuilt from the live repository graph, its protected half
cannot change without explicit authorization, and drift in it fails
`architecture:check`. When `docs/` and the code disagree, that is a defect with a
gate attached.

Project Intelligence is a **retained analysis**. It is regenerated by a language
model on demand, nothing validates it, and no gate notices when it goes stale.
It is useful for orientation — "why is this shaped this way", "what is risky
here" — and it is not evidence.

The skill states the precedence itself, and it is the right one:

```text
Current Implementation → Project Documentation / Rules → Persistent Knowledge Files → Previous Assumptions
```

A knowledge file never outranks `docs/`, and `docs/` never outranks the code.
Where this repository's own agent rules apply, they come first: see
[document-mutability.md](./document-mutability.md) and the working rules in
`CLAUDE.md`.

## Retraining

```bash
npm run intelligence:retrain
```

`scripts/retrain-project-intelligence.ts` spawns the Antigravity CLI —
`agy --dangerously-skip-permissions -p <prompt>` — with a nine-phase prompt
built into the script: load the current knowledge, inspect the repository,
criticize what is already written, discover what is missing, compare knowledge
against reality, improve the base, evaluate the system itself, validate, and
consolidate. Extra CLI arguments are forwarded.

Three things about this command are worth knowing before running it.

**It is not model fine-tuning.** Nothing about the model changes. The command
rewrites Markdown files under `knowledge/`.

**It runs with permission checks disabled.** `--dangerously-skip-permissions`
means the spawned agent is not prompted before acting. The prompt instructs it
not to modify production application code, but that is an instruction, not a
sandbox — review the resulting diff before keeping it.

**It is the one sanctioned use of `agy` in this repository.** The Local Runner
policy in
[local-runner-full-host-control.md](../07-mobile-and-release/local-runner-full-host-control.md)
forbids Antigravity in a *dispatched job*; `intelligence:retrain` is a
developer-invoked local command and is exempt. That exemption is why no PATH
refusal shim was ever installed.

The command is absent from the generated command catalogs' release surface on
purpose: it publishes nothing, deploys nothing, and touches no runtime.

## When to distrust it

- After any change that moved package boundaries, ports, or ownership — the
  knowledge files are not regenerated by a gate and will still describe the old
  shape.
- Whenever a knowledge file and a document under `docs/` disagree. Resolve it
  against the code, then fix `docs/` if `docs/` was wrong.
- For any command, path, environment key, or route: prefer the live Context Pack
  (`npx tsx scripts/docs/context.ts <target>`), which is rebuilt from the
  repository every time it runs.
