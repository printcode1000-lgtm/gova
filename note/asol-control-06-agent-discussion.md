## ترتيب التنفيذ والحالات المرجعية

1. الوكيل 1 ينشئ أساس `control` وdeclaration/runner ويعلن hash الأساس، من دون تغيير workflow الفعلي أو نشر كامل.
2. الوكيل 2 يعمل فوق hash الوكيل 1، يثبت مصفوفة route+method، ويعلن hash التسليم.
3. الوكيل 3 يعمل فوق hashes الوكيلين 1 و2، ينقل كل handlers إلى mirrors، ويعلن hash التسليم مع تقرير manifests.
4. الوكيل 4 يعمل فوق hashes الوكلاء 1 و2 و3، ويثبت 410 guard دون تغيير source handlers، ويعلن hash التسليم.
5. الوكيل 5 يدمج محليًا بالترتيب 1 ثم 2 ثم 3 ثم 4، ثم يضيف الوثائق/واجهة الحسابات ويشغّل الفحوص الشاملة. لا توجد مراجع متباعدة أو HEAD غير محدد في أي تسليم.

كل مدخلة تسليم تذكر: hash الأساس، hash commit التسليم، ملفات التغيير، نتائج الاختبار، routes المتأثرة، ومفاتيح env بالأسماء فقط. لا يبدأ الوكيل التالي من ادعاء شفهي أو من branch متحرك.

## قرار مانع: إشعار النشر

الوضع الحالي يرسل `gova` server request إلى notifications عند حدث نشر. هذا يخالف قاعدة العزل الجديدة. قبل أن ينقل الوكيل 1 هذا السلوك، يطلب قرار المالك ويكتب واحدًا فقط: إلغاء الإشعار، أو browser-delivered signed grants. لا يوجد حل ثالث يقوم فيه webhook أو control باستدعاء notifications خلفيًا.

## تعريف النجاح

- `gova` production يرد 410 لكل business API ولا يشغل handler.
- كل route+method سابق له owner واحد قابل للوصول من المتصفح.
- Auth يعمل cross-origin بsession/CORS محكومين، لا بحقل uid أو fallback محلي.
- `asol-control` يتحكم بالنشر وبـops، ولا يعد خدمة منتج سابعة.
- نشر `main` الوحيد يبدأ من revision موحد ثم يتحقق من الخدمات الست وgova.

## ميثاق عزل حسابات Vercel

- GitHub يتصل بـ`gova` فقط. كل حساب آخر CLI/Sandbox-only ولا يأخذ Git integration.
- لا خدمة runtime تعرف حسابًا شقيقًا: لا credentials ولا project/team ID ولا URL ولا backend call ولا declaration mirror أجنبي.
- العميل فقط يحمل public endpoint URLs، ويصل إليها مباشرة من browser/static/Android/iOS مع `credentials: omit` و`x-asol-session-token` عند الحاجة.
- `asol-control` يحمل deploy targets في runner المشفر فقط لتنفيذ `deploy:all`؛ لا تملك routes الخاصة به هذا السجل ولا تفصح عنه. هذا استثناء الإدارة الوحيد.
- أي نتيجة تدقيق مخالفة لهذه البنود مانعة للدمج المحلي.

## بروتوكول أسرار الوكلاء

- كل وكيل مخول لبيئة الأسرار المحلية الكاملة اللازمة للتنفيذ والتحقق، عبر archive/secret store المشترك فقط.
- هذا وصول للوكيل، لا تفويض لتسريب السر إلى حساب Vercel غير مالكه: runtime لكل حساب يأخذ أقل صلاحياته فقط.
- يمنع وضع قيم الأسرار في المحادثة أو `note/` أو commits أو logs. يستخدم الوكيل `npm run secrets:verify` لتقرير الأسماء والحالات فقط.
- بعد اعتماد النتيجة، تدوّر كل الأسرار التي أتيحت للوكلاء، ثم يحفظ archive جديد محليًا؛ لا GitHub push.
